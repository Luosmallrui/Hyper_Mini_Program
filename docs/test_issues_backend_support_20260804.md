**实测**：携带有效商家 token 调用返回：

```json
{ "code": 500, "msg": "sql: expected 4 arguments, got 3" }
```

**影响**：小程序管理后台账户页品牌卡回退为兜底值（名称显示 "POWER FLOW"、认证状态不可信）；该接口是 `fetchAccount` 的唯一数据源。

**前端已做的兼容**（可长期保留，也可在接口修复后回退）：主办方编辑/区域/认证信息的回显与展示已改走 `GET /api/v1/organizer/profile`（该接口正常）；保存后的品牌卡刷新失败不再阻断保存流程。

**需要后端**：修复该 SQL 错误（疑似今晚改动引入的参数个数问题）。

## 3. 【待确认】商家密码登录返回 `refresh_token`（对应问题 #6 关联风险）

- 问题 #6 本身（发布后跳登录页）是前端跳转错误，已修复。
- 但前端 401 自动续期依赖 `refresh_token`：若 `POST /api/v1/auth/login-password` 不返回 `refresh_token` / `access_expire`，商家账号任何一次 401 都会清空登录态，触发真正的退出登录。

**需要后端**：确认 `login-password` 响应是否包含 `refresh_token`、`access_expire`；如缺失请补齐。
