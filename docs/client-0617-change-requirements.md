# 客户端 0617 修改要求与前后端分工

来源：`docs/Hyper小程序开发进度表_0617.xlsx`

## 0. 范围确认

以下内容本轮不作为待修改项处理：

- 头像、昵称获取/编辑：已人工确认可用，不再改。
- 消息模块：私信展示、一键已读、发送私信后列表刷新、消息详情等已人工确认可用，不再改。
- 个人中心“账号中心入口”：保留，不删除。
- 售后订单：不新增独立模块，统一在现有“订单”页内增加售后状态 tab。

## 1. 首页搜索、区域和筛选

### 前端需要做

- 搜索框输入关键词后，确保进入搜索结果页或刷新当前列表，并展示匹配商家、活动、场地。
- 首页列表和地图请求统一携带关键词、距离、行政区/商圈、标签等筛选参数。
- 行政区/商圈切换后，下方列表必须有可感知变化；后端字段不足时先做客户端兜底过滤。
- 更多筛选中的“积分立减、买单立减、新人优惠”等标签需要有选中态、清除态和列表变化。
- 距离筛选若后端未配置，前端需展示可用兜底项，例如 1km、3km、5km、10km。

### 后端/API 需要做

- `/api/v1/search`、`/api/v1/map/markers`、`/api/v1/merchant/list` 或当前列表接口需要支持：
  - `keyword`
  - `distance`
  - `district` / `area`
  - `business_area`
  - `tags`
  - `lat/lng`
- 返回数据需要包含足够的筛选字段，例如行政区、商圈、经纬度、优惠标签、是否支持积分抵扣。
- 管理端需要能配置距离筛选项；若暂未提供，前端先用默认距离项。

### 验收口径

- 输入明确关键词后能看到对应结果或明确空态。
- 切换行政区/距离/标签后，请求参数变化，列表或空态同步变化。

## 2. 积分体系与购票抵扣

### 前端需要做

- 购票抽屉展示积分余额、预计抵扣金额、实际支付金额。
- 用户可手动选择是否使用积分。
- 下单时传入积分使用字段。
- 积分不可用、余额不足、后端拒绝时展示明确提示。

### 后端/API 需要做

- 提供积分余额接口：

```http
GET /api/v1/points/balance
```

建议响应：

```json
{
  "code": 200,
  "data": {
    "balance": 300
  }
}
```

- 购票成功后按规则发放积分：
  - 默认 `10 元消费 = 1 积分`，四舍五入保留正整数。
  - 积分兑换比例可由平台后台配置。
- 创建订单接口需支持积分抵扣：

```json
{
  "use_points": true,
  "points_amount": 100
}
```

- 后端必须校验积分余额、抵扣比例、活动是否允许抵扣，并返回实际抵扣结果。
- 需要提供积分流水，用于“积分账户”展示。

### 验收口径

- 有积分账号可看到余额。
- 勾选积分抵扣后，支付金额变化。
- 订单创建后返回实际抵扣结果，积分流水增加。

## 3. 删除店铺售卖商品、商品订单相关功能

### 前端需要做

- 客户端删除或隐藏店铺售卖商品入口、商品详情、商品下单、商品订单等功能。
- 场地详情中不再展示商品售卖模块。
- 订单页只保留票务订单和售后相关能力。

### 后端/API 需要做

- 若后端仍保留旧商品接口，前端不再调用。
- 管理端/商家端同步删除或隐藏商品管理、商品订单管理入口。

### 验收口径

- 客户端无法从任何入口进入商品购买和商品订单。
- 票务购票、票务订单不受影响。

## 4. 场地相关动态与动态评论

### 前端需要做

- 场地详情的相关动态列表增加空态，不出现空白或异常字符。
- 动态评论回复后立即更新评论列表。
- 修复“初次评论其他评论以后导致黑色蒙版、页面卡住”的问题。
- 我的动态为空时展示正常空态文案，不出现未知字符。

### 后端/API 需要做

- 场地详情相关动态需要提供可测试数据，或接口返回明确空列表。
- 评论/回复接口返回新增评论实体，至少包含：
  - `id`
  - `content`
  - `user`
  - `created_at`
  - `reply_to` 或父评论字段

### 验收口径

- 评论后可继续回复，页面不卡死。
- 回复成功后当前页立即出现回复内容。
- 无动态时展示规范空态。

## 5. 订单与售后状态

### 前端需要做

- 当前“订单”页增加售后相关 tab，不新增独立售后模块。
- 需要增加的 tab：
  - 待审核
  - 退款中
  - 已退款
  - 已驳回
  - 已取消
- 待支付订单必须出现在“待支付”列表。
- 待支付订单增加“继续支付”按钮，调用预支付接口重新拉起支付。
- 订单列表状态、按钮和空态按订单/退款状态正确展示。

### 后端/API 需要做

- `GET /api/v1/order/list` 需要支持订单状态和售后状态筛选。
- 如果售后状态不属于订单主状态，需返回统一字段，例如：

```json
{
  "order_no": "T202606130001",
  "status": 1,
  "refund_status": "pending_review",
  "refund_no": "R202606130001"
}
```

- 建议售后状态枚举：
  - `pending_review`：待审核
  - `refunding`：退款中
  - `refunded`：已退款
  - `rejected`：已驳回
  - `cancelled`：已取消
- 继续支付需要支持：

```http
POST /api/v1/pay/prepay
```

请求：

```json
{
  "order_no": "T202606130001"
}
```

### 验收口径

- 每个 tab 能请求并展示对应状态订单。
- 待支付订单可重新支付。
- 退款申请后的订单能进入对应售后 tab。

## 6. 我要入驻与商家后台准入

### 前端需要做

- “我要入驻”申请表中的省市区改为三级选择，不再手动输入。
- 提交申请后，再次进入显示“审核中”状态，不允许重复提交。
- 审核中不能进入商家后台。
- 审核不通过时展示不通过原因，并允许修改资料重新提交。

### 后端/API 需要做

- 入驻申请提交接口：

```http
POST /api/v1/organizer/apply
```

- 审核状态接口：

```http
GET /api/v1/organizer/audit-status
```

建议响应：

```json
{
  "code": 200,
  "data": {
    "status": "pending",
    "reject_reason": "",
    "organizer_id": 3
  }
}
```

- 后台管理端必须能看到入驻审核列表并处理通过/驳回。
- 用户信息接口需要返回是否已成为主办方/商家，以及审核状态。

### 验收口径

- 提交后客户端展示审核中。
- 后台能看到申请记录。
- 审核状态变化后客户端入口同步变化。

## 7. 商家端核销

### 前端需要做

- 扫码核销票务订单当前已支持，本轮重点检查核销后是否能看到核销记录。
- 展示核销成功、失败、重复核销、无效码等结果页。
- 允许主办方绑定/管理核销员。

### 后端/API 需要做

- 扫码识别：

```http
POST /api/v1/verifier/scan
```

- 确认核销：

```http
POST /api/v1/verifier/confirm
```

- 核销记录：

```http
GET /api/v1/verifier/verified-list
```

- 需要确认核销成功后 `GET /api/v1/verifier/verified-list` 能返回对应记录。

### 验收口径

- 有效票能核销成功，且核销记录列表能看到该记录。
- 已核销票再次扫码提示重复核销。
- 无效码展示失败结果。

## 8. 商家等级体系

### 前端需要做

- 商家端展示当前等级、手续费比例、升级条件。
- 默认规则：
  - 1 级：手续费 5%
  - 办理 5 场活动升 2 级：手续费 3%
  - 办理 10 场活动升 3 级：手续费 0%
- 删除商家端活动抽奖及相关配套配置入口。

### 后端/API 需要做

- 用户/商家信息接口返回等级、手续费比例、已举办活动数、下一等级条件。
- 平台后台需支持等级规则配置，或先按默认规则返回。

建议字段：

```json
{
  "level": 1,
  "fee_rate": 0.05,
  "completed_activity_count": 3,
  "next_level_required_count": 5
}
```

### 验收口径

- 商家端能看到等级和手续费。
- 活动办理数量变化后等级信息可更新。

## 9. 实施优先级

1. 删除废弃商品/抽奖入口，避免无效功能继续暴露。
2. 修复首页搜索、筛选、订单待支付和继续支付。
3. 完成订单页售后 tab。
4. 完成积分抵扣闭环。
5. 修复动态评论回复和空态。
6. 完善入驻审核状态和商家后台准入。
7. 验证核销记录列表是否能展示核销成功记录。

## 10. 需要后端优先确认的问题

- 首页筛选接口是否统一走 `/api/v1/search`，还是首页列表、地图、商家列表分别实现筛选。
- 售后状态是否通过 `order.status` 表示，还是新增 `refund_status`。
- 积分抵扣比例和是否允许活动抵扣由哪个接口返回。
- 入驻审核状态接口是否已能区分未提交、审核中、通过、驳回。
- 核销成功后 `GET /api/v1/verifier/verified-list` 是否能立即返回对应记录。
- 商家等级规则是后台可配置，还是先使用默认规则。
