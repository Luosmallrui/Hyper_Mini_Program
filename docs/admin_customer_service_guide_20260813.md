# 客服工作台配置与使用指南

更新时间：2026-08-13

接口契约详见 [`admin_customer_service_workbench_api_20260812.md`](./admin_customer_service_workbench_api_20260812.md)。本文档面向运营/管理员，说明客服链路的配置方法与日常使用方式。

## 1. 功能概览

- 小程序用户通过消息页「客服消息」固定入口，与**平台客服账号**进行站内 IM 单聊。
- 管理员在 PC 管理端「客服工作台」（`/admin/customer-service`）查看会话并回复。
- 复用既有 IM 链路（单聊消息、会话未读、消息队列投递、Socket 推送），不创建第二套聊天数据。
- 用户看到的回复发送者始终是平台客服账号，不暴露具体管理员身份。
- 管理员的回复、标记已读操作会写入管理员操作日志。

## 2. 首次上线配置

### 2.1 准备客服账号

准备一个**正常状态**的平台用户账号作为对外的「Hyper 客服」：

1. 在小程序正常注册一个用户账号。
2. 建议设置昵称（如「Hyper 客服」）、头像、签名（如「在线客服」），这些信息会展示给用户。
3. 记录该账号的用户 ID（数值）。

### 2.2 数据库预置配置项

已有数据库需执行一次（新库可跳过，由初始化脚本带入）：

```sql
INSERT IGNORE INTO platform_settings (setting_key, setting_value, remark)
VALUES ('customer_service_user_id', '0', '客服聊天用户 ID');
```

### 2.3 设置客服账号 ID

超级管理员登录 PC 管理端，进入「系统」配置页，将客服聊天用户 ID 设置为上述账号 ID；或直接调用：

```http
PUT /api/v1/admin/system-config
Authorization: Bearer <admin_access_token>
Content-Type: application/json
```

```json
{
  "customer_service_user_id": 52
}
```

### 2.4 未配置的兜底行为

`customer_service_user_id` 未配置、为 `0`、账号不存在或已被停用时，工作台接口返回：

```json
{
  "code": 409,
  "msg": "客服工作台未配置客服账号"
}
```

PC 工作台此时展示「请先在系统配置中设置客服聊天用户 ID」。

## 3. 权限分配（RBAC）

- 新增权限点：`admin.customer_service`（客服工作台）。
- 超级管理员（`*`）自动拥有，无需配置。
- 非超级管理员：在「系统 → 角色管理」中，为角色勾选「客服工作台」权限后，该角色下的管理员即可看到侧边栏「客服」菜单。
- 无权限的管理员访问 `/admin/customer-service` 会被 RBAC 守卫拦截。

### 操作审计

| 操作 | 日志动作 |
|---|---|
| 以客服身份回复 | `admin.customer_service.reply` |
| 标记会话已读 | `admin.customer_service.read` |

## 4. PC 工作台使用

入口：管理端侧边栏「客服」（`/admin/customer-service`）。

### 4.1 会话列表（左栏）

- 按最后消息时间倒序展示所有与平台客服账号的单聊会话。
- 支持按**客户昵称、手机号或数值用户 ID**搜索（Enter 或点击查询按钮）。
- 每条会话显示客户头像、昵称、手机号、最后消息预览、时间和**未读数**（客服账号侧未读）。
- 列表每 **10 秒**自动刷新，新会话和新消息会自动出现；也可手动点「刷新」。
- 会话超过一页时，底部「加载更多」翻页。

### 4.2 聊天面板（右栏）

- 点击左侧会话即加载聊天记录，并**自动标记已读**（以当前最后一条消息时间为准）。
- 进入后每 **5 秒**增量拉取新消息；正在查看时客户发来新消息会即时上屏并重新标记已读。
- 顶部「加载更早的消息」可上翻历史（cursor 分页）。
- 回复：输入框 **Enter 发送，Shift+Enter 换行**；发送成功后消息立即出现在列表中。
- 消息左右侧按接口返回的 `is_self` 判定（`true` = 平台客服发出），与当前登录的管理员无关。
- 文本消息直接展示；图片消息展示缩略图；其余类型（语音/视频/文件/卡片等）以 `[类型]` 占位展示。

### 4.3 异常提示

| 场景 | 表现 |
|---|---|
| 未配置客服账号（409） | 整页提示「请先在系统配置中设置客服聊天用户 ID」 |
| 用户从未咨询过（404） | 聊天区提示「客服会话不存在，请等待用户先发起咨询」 |
| 登录过期（401） | 自动退出到管理员登录页 |

> 注意：管理员不能通过工作台查看任意用户之间的私信，也不能向从未咨询过的用户主动发起客服消息。

## 5. 用户侧（小程序）说明

- 入口：消息页顶部「客服消息」固定入口。客服会话不会单独出现在聊天列表中，统一合并进该入口。
- 小程序端通过 `GET /api/v1/user/customer-service` 获取平台客服账号（不写死用户 ID），再进入标准单聊页。
- 管理员离线时用户消息正常落库；用户离线时客服回复同样落库，用户下次进入小程序即可查看。
- 订单详情页的「联系客服」是客服电话弹窗，与站内客服消息是两条独立通道。

## 6. 常见问题

**工作台打开提示未配置客服账号？**
按「2. 首次上线配置」设置 `customer_service_user_id`，并确认该账号处于正常状态（未停用）。

**侧边栏看不到「客服」菜单？**
当前管理员角色缺少 `admin.customer_service` 权限，请在角色管理中勾选，或使用超级管理员账号。

**回复后用户没收到？**
回复接口成功即代表消息已进入既有 IM 投递链路（消息队列 + Socket 推送）。用户在线时实时到达，离线时下次进入小程序通过会话历史查看。若接口本身报错，按 toast 提示与操作日志排查。

**未读数没有清零？**
已读接口以后端校验为准：仅当会话最后一条消息时间不晚于上报的 `read_time` 时才清零。管理员查看期间新到的消息会保留未读，属于预期行为，继续查看即可再次标记。

**可以更换客服账号吗？**
可以，系统配置中修改 `customer_service_user_id` 即可。更换前请与后端确认历史会话的归属行为，避免老会话落到旧账号上无人处理。
