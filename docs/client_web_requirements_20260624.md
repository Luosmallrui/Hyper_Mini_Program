## 一、修订口径

### 1. “我要入驻”的来源与正确理解

表格来源：

- `开发进度表` 客户端部分：第 88 行“我要入驻”、第 89 行“审核结果”、第 90 行“商家端”。
- `开发进度表` 商家 PC 部分：第 95 行“通过客户端入驻申请，审核通过后绑定手机号作为商家端账户”。
- `开发进度表` 商家 PC 部分：第 103 行“商家完成入驻申请后，不可重复提交申请”。
- `调整项说明`：第 3 条“增加我要入驻申请界面...审核通过后获得商家后台权限...审核不通过可修改资料重新提交”。

修订后的业务口径：

- “我要入驻”是当前小程序用户发起商家 / 场地主体入驻申请的入口。
- “我要入驻”不能等同于“主办中心 / 管理后台登录权限”。
- 用户即使没有用当前小程序账号提交入驻申请，也应允许通过“主办中心 / 管理后台”进入已有商家账号登录、组织授权或组织切换流程。
- 审核中状态只禁止当前用户重复提交同一入驻申请，不应阻断用户使用已有商家账号或被授权组织。
- 审核通过后，当前用户获得对应商家权限；审核驳回后，展示驳回原因并允许修改后重新提交。

### 2. 入驻接口状态更新

以下接口已经在现有文档、网页端代码封装和后端更新文档中确认，不应再写成“需要后端新增”：

- `POST /api/v1/organizer/apply`
- `GET /api/v1/organizer/audit-status`

2026-06-24 后端更新已确认：

- `audit-status` 返回 `organizer_id`、`type`、`status`、`enabled`、`reject_reason`、`submitted_at`、`reviewed_at`。
- `status` 仍表示入驻审核：`0` 未提交 / 待提交，`1` 审核中，`2` 已通过，`3` 已驳回。
- `enabled` 表示商家账号启停：`1` 可使用，`0` 已停用。
- 审核中重复提交会被后端拒绝；已驳回允许修改资料后重新提交。
- `GET /api/v1/organizer/info` 可返回待审核、已驳回和已停用商家的状态信息。
- 其它商家业务接口要求商家已通过且已启用。

## 二、小程序端待处理 / 需确认

### 1. 个人中心入口调整

2. “管理后台 / 主办中心”入口应优先进入商家账号登录、组织选择或已授权组织入口。

4. 若当前用户入驻已通过，可提示从管理后台进入当前用户所属商家后台。
5. 若当前用户入驻被驳回，点击“我要入驻”展示驳回原因并允许修改后重新提交。
6. 若商家账号 `enabled=0`，商家后台需展示“商家账号已停用”类状态，不继续进入业务页面。

后端接口状态：
