# MVP Scope

本文件定义 Claude Code 第一轮最小可交付范围。后端接口尚未完成，第一轮必须 mock-first，不接真实后端。目标是先让 P0 后台管理主链路可打开、可交互、可验证，不一次性吞下全部 21 个页面。

## 第一轮必须完成的最小功能

1. 后台管理入口 `pages/user-sub/organizer/index` 可打开、可编译。
2. 后台首页能展示空态和有活动状态。
3. 活动中心列表能展示 mock 数据、空态、loading、error。
4. 活动中心搜索可输入、确认、清空，并刷新列表或本地过滤。
5. 活动中心筛选可打开、选择、重置、应用。
6. 日期范围选择可打开、选择开始/结束、清空、应用。
7. P0 活动发布向导至少能完成第 1 步和第 2 步的状态暂存与下一步/上一步。
8. 对已有 mock 和现有内部视图保持兼容，不破坏其他页面。
9. 页面通过 organizer 模块 adapter 或局部 helper 读取 mock 数据，不直接调用 proposed 接口。
10. 不修改全局 request 封装。
11. 用户主页左上角按蓝湖补齐 `扫一扫` + `客服` 图标组；扫码只对 active 核销员展示，客服有有效反馈。

## 第一轮可以暂缓的页面

- 上传海报完整裁剪、压缩、比例处理：可放到 Batch 3。
- 票券配置完整保存和复杂库存规则：可放到 Batch 3。
- 核销、添加核销员、核销成功/失败弹窗：可放到 Batch 4。
- 提现信息编辑和审核状态页：可放到 Batch 5。
- P1/P2 页面视觉微调：可暂缓。

## 必须做成真实可交互的功能

- 内部 tab 切换。
- 搜索输入和清空。
- 筛选面板打开/关闭。
- 筛选项选择/重置/应用。
- 日期范围弹窗打开/关闭/应用。
- 列表数据、空态、loading、error 状态切换。
- 发布向导第 1/2 步上一步/下一步。
- 基础表单非空校验。
- 用户主页左上角客服入口可点击，有客服会话、项目客服承接或 Toast/TODO。
- active 核销员左上角扫码入口可点击，并进入订单核销 mock 流程。

## 可以先用 mock 的功能

- 后台首页统计数据。
- 活动列表查询和分页。
- 活动草稿保存。
- 地图定位结果。
- 图片上传结果。
- 票券保存结果。
- 核销券码结果。
- 核销员列表和保存。
- 提现信息查看和编辑。

## 第一轮禁止接真实后端

- 不调用 `/api/biz/organizer/*`。
- 不新增真实接口路径常量。
- 不修改全局 request 封装。
- 不把 proposed contract 当 existing API。
- 不把 mock 数据散落到大量页面组件中。

## 不应阻塞编码的 unknown

- 蓝湖真实上传时间。
- P1/P2 节点级尺寸不完整。
- 图标是否必须使用蓝湖切图。
- 后台接口真实路径和后端响应字段。
- 权限字段命名。
- 复杂状态枚举最终命名。

## 必须人工确认后才能继续的 unknown

- 是否要新增独立后台/核销路由或修改 `app.config.ts`。
- 是否接入真实 `/api/biz/organizer/*` 接口。
- 真实权限体系和按钮可见性。
- 真实核销错误码和可核销时间规则。
- 提现账号、银行卡、实名校验规则。
- 上传图片的真实大小、比例、裁剪、压缩、OSS/签名规则。
- 票券价格单位、库存上限、退款/上下架规则。

## MVP 验收边界

- MVP 不是像素级最终还原。
- MVP 不接真实后端。
- MVP 不是完整权限体系。
- MVP 的完成标准是：P0 主链路可运行，核心交互可用，mock 数据清晰，adapter 边界清楚，TODO 标记明确，后续 Batch 可继续叠加。
